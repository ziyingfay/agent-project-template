# 轻量文件管理规范

> 本规范用于小规模 Agent / Coding Agent 项目。目标是让不熟悉工程目录的同事也能快速判断：文件是什么、从哪来、能不能删、和哪个任务或测试有关。

---

## 一、一级目录不变

项目一级目录保持简单：

```text
ProjectName/
├── skills/      # Agent skills 主交付区
├── app/         # 可选支撑应用、demo、工具代码
├── reference/   # 参考资料
├── dev/         # 项目管理、日志、测试、临时工作区
└── outputs/     # 对外可查看的产物
```

---

## 二、二级目录规则

### `skills/` - Agent skill 交付区

| 目录 | 放什么 | 能否清理 |
|------|--------|----------|
| `active/` | 当前正在使用或准备交付的 skill 包 | 不能随意清理 |
| `drafts/` | 尚未定稿的 skill 草稿、试验版本 | 可定期清理，清理前确认 |
| `examples/` | skill 使用样例、输入输出示例 | 不能随意清理 |
| `test-fixtures/` | 测试用输入数据、测试夹具 | 不能随意清理，除非测试已废弃 |
| `archive/` | 旧版本、废弃版本、历史包 | 可归档压缩，不建议直接删除 |

### `app/` - 可选支撑应用区

| 目录 | 放什么 | 能否清理 |
|------|--------|----------|
| `src/` | 正式支撑应用或工具代码 | 不能随意清理 |
| `prototypes/` | 临时 demo、页面原型、技术试验 | 可清理，清理前确认是否还要参考 |
| `tests/` | 应用代码相关测试 | 不能随意清理 |
| `archive/` | 旧 app 版本或废弃实现 | 可归档压缩，不建议直接删除 |

### `reference/` - 参考资料区

| 目录 | 放什么 | 能否清理 |
|------|--------|----------|
| `requirements/` | PRD、需求文档、客户说明 | 不能清理 |
| `source-materials/` | 原始素材、旧系统文件、用户提供资料 | 不能清理 |
| `research/` | 调研资料、竞品分析、技术参考 | 可整理，不建议删除 |
| `examples/` | 可参考的外部样例、历史样例 | 可整理，不建议删除 |
| `archive/` | 过期但可能还要追溯的参考资料 | 可归档压缩 |

### `dev/` - 项目记忆和工作区

| 目录/文件 | 放什么 | 能否清理 |
|-----------|--------|----------|
| `current-state.md` | 当前阶段、当前焦点、下一步 | 不能清理 |
| `docs/` | 决策、问题、测试、里程碑、规范 | 不能清理 |
| `notes/` | 工作日志、聊天记录、技术笔记 | 不能清理 |
| `scripts/` | 项目辅助脚本 | 不能随意清理 |
| `temp/scratch/` | 临时试算、随手草稿 | 可清理 |
| `temp/drafts/` | 临时文案、半成品草稿 | 可清理，清理前确认 |
| `temp/test-runs/` | 临时测试输出、一次性运行结果 | 可清理 |

### `outputs/` - 对外产物区

| 目录 | 放什么 | 能否清理 |
|------|--------|----------|
| `final/` | 已确认、可交付、可展示的最终产物 | 不能清理 |
| `drafts/` | 可展示但未定稿的产物 | 可清理旧版本，保留最近版本 |
| `samples/` | 当前样例、演示样例、标准示例 | 不能随意清理 |
| `test-results/` | 测试产物、测试截图、测试报告 | 可清理旧测试，测试记录保留 |
| `archive/` | 旧版产物、历史交付物 | 可归档压缩 |

## 三、文件命名规则

推荐格式：

```text
YYYYMMDD-关联ID-类型-简短说明-v版本号.ext
```

示例：

```text
20260603-T001-test-result-chat-logger-v01.md
20260603-TASK002-draft-skill-spec-imagegen-v02.md
20260603-M1-sample-email-parser-v01.json
20260603-FINAL-skill-package-chat-logger-v01.zip
```

### 字段说明

| 字段 | 说明 | 示例 |
|------|------|------|
| `YYYYMMDD` | 产出日期 | `20260603` |
| `关联ID` | 任务、测试、里程碑或最终交付编号 | `TASK002`、`T001`、`M1`、`FINAL` |
| `类型` | 文件性质 | `draft`、`sample`、`test-result`、`final`、`reference` |
| `简短说明` | 3-6 个英文单词或拼音/中文短词 | `chat-logger`、`skill-spec` |
| `v版本号` | 两位版本号，从 `v01` 开始 | `v01`、`v02` |

---

## 四、常用类型词

| 类型词 | 含义 | 应放目录 |
|--------|------|----------|
| `draft` | 草稿、未定稿 | `outputs/drafts/` 或 `dev/temp/drafts/` |
| `sample` | 当前样例、标准示例 | `outputs/samples/` 或 `skills/examples/` |
| `test-result` | 测试产物、测试输出 | `outputs/test-results/` 或 `dev/temp/test-runs/` |
| `final` | 最终确认产物 | `outputs/final/` |
| `fixture` | 测试输入、测试夹具 | `skills/test-fixtures/` |
| `reference` | 参考资料 | `reference/` |
| `archive` | 历史归档 | `archive/` |

---

## 五、版本号规则

- 第一次产出用 `v01`。
- 内容有实质变化时递增：`v02`、`v03`。
- 只修错别字或轻微格式，可以不新增版本。
- 用户确认后的最终版放入 `outputs/final/`，文件名类型改为 `final`。
- 不要使用 `new`、`final_final`、`latest` 这类不可追溯命名。

---

## 六、清理规则

### 可以清理

- `dev/temp/scratch/`
- `dev/temp/test-runs/`
- `outputs/test-results/` 中很旧且已记录到 `测试记录.md` 的测试产物
- `outputs/drafts/` 中过期草稿，保留最近 1-3 个版本
- `app/prototypes/` 中确认不用的原型
- `skills/drafts/` 中确认不用的草稿

### 不要清理

- `AGENTS.md`
- `dev/current-state.md`
- `dev/docs/`
- `dev/notes/`
- `skills/active/`
- `skills/examples/`
- `skills/test-fixtures/`
- `outputs/final/`
- `outputs/samples/`
- `reference/requirements/`
- `reference/source-materials/`

### 清理前检查

清理前先问三个问题：

1. 这个文件是否已经被记录到 `测试记录.md`、`工作日志` 或 `需求变更日志`？
2. 这个文件是否是用户确认过的最终版或当前样例？
3. 这个文件是否和某个测试 ID、任务 ID、里程碑有关？

只要有一个答案是“是”，就不要直接删除，先移动到 `archive/`。
