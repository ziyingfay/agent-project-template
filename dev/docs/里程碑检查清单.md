# 里程碑检查清单

> 本文档定义每个阶段的完成标准。里程碑完成前，Codex 先自检；需要用户验收时，再请用户确认。

---

## M1 | Intent + Skill Design

**目标：** 明确 skill 或项目的目标、边界、触发条件、验收标准。  
**状态：** Not Started

| 检查项 | 验收标准 | 状态 | 备注 |
|--------|----------|------|------|
| 目标明确 | 能用 3-5 句话说明为什么做 | Pending | |
| 用户明确 | 目标使用者和使用场景清楚 | Pending | |
| 触发条件明确 | 知道什么时候应该使用 skill | Pending | |
| 非目标明确 | 明确哪些事情不做 | Pending | |
| 验收标准明确 | 有可检查的完成标准 | Pending | |

---

## M2 | Build + Test

**目标：** 完成 skill 文件、脚本、样例，并通过基本测试。  
**状态：** Not Started

| 检查项 | 验收标准 | 状态 | 备注 |
|--------|----------|------|------|
| 文件结构完整 | `SKILL.md`、必要脚本、参考资料、样例齐全 | Pending | |
| 流程可执行 | Codex 能按说明执行一轮任务 | Pending | |
| 最小样例通过 | 至少 1 个最小样例验证通过 | Pending | |
| 真实样例通过 | 至少 1 个贴近实际的样例验证通过 | Pending | |

---

**目标：** 整理为可复制/安装/复用的项目产物，并更新项目记忆。

| 检查项 | 验收标准 | 状态 | 备注 |
|--------|----------|------|------|

| 测试记录完成 | 测试结果写入 `测试记录.md` | Pending | |

| 当前状态更新 | `dev/current-state.md` 已更新 | Pending | |
