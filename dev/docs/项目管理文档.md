## 五、Agent Skill 轻量开发流程

本项目默认面向个人或 1-3 人小团队，不采用重型软件工程流程。除非用户明确要求完整 Web App，否则优先使用以下轻量流程：

| 阶段 | 目标 | 主要产物 | 是否需要用户确认 |
|------|------|----------|------------------|
| Intent | 明确要解决的问题、使用者、触发条件、边界 | 简短需求说明、验收标准 | 需要 |
| Skill Design | 设计 skill 的行为和文件结构 | `Skill开发说明.md` 或 skill spec | 重要 skill 需要 |
| Build | 编写/修改 `SKILL.md`、脚本、示例 | `skills/<skill-name>/` | 通常不需要 |
| Test | 用真实样例验证 skill 是否有效 | `测试记录.md` | 失败或风险较高时需要 |
| Package | 整理成可复制/安装的包 | skill 目录、README、示例 | 发布前需要 |
| Review | 更新状态和工作记忆 | `current-state.md`、工作日志 | 不需要 |

### 确认点原则

- 小任务：Codex 可以直接执行并记录结果。
- 新 skill / 大改动：Intent 完成后先确认。
- 发布、迁移、删除、覆盖重要文件：执行前确认。
- 用户已经给出明确方向时，不为了流程而反复打断。

## 八、文档维护规则

- 需求和关键决策必须进入 `需求变更日志.md`。
- 发现问题必须进入 `问题跟踪.md`。
- 执行测试必须进入 `测试记录.md`。
- 阶段、焦点、下一步变化时更新 `dev/current-state.md`。
- 创建、移动、归档、清理文件时遵守 `文件管理规范.md`。
- 每次较完整的工作会话后更新 `dev/notes/work-log-YYYYMMDD.md`。
